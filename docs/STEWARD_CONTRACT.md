# Steward 生命周期契约

> **适用**：`AtriumCppTools` 下所有工具
> **状态**：权威契约，宿主侧实现必须与此对齐
> **上位依据**：`AtriumSteward/Docs/ARCHITECTURE_DESIGN.md`
> **来源**：从 `README.md` §5 拆分而来（2026-09-19 文档瘦身）

> 本节是本仓库存在的理由。任何工具在接入 `Steward` 前，必须先满足本文档全部条目。

## 1. 契约原则

1. `Steward` 只通过 **manifest + 协议** 调用工具，禁止源码直连（依据 v5 红线 `V5-S4`）。
2. **生命周期归宿主**：`Steward` 决定工具的启动、停止与重启；**状态归工具**：工具自己实现业务状态机。
3. **渐进增强**：manifest 出现未知字段时，`Steward` 必须忽略而非报错；协议版本不匹配时，工具必须拒绝服务并给出明确退出码，而不是降级静默运行。
4. **单向依赖**：工具可以读取 `Steward` 传入的上下文，禁止工具反向调用 `Steward` 内部接口。

## 2. 工具清单：`tool.manifest.json`

每个工具必须在 `Docs/` 下提供 manifest，字段最小集：

| 字段 | 必填 | 说明 |
| :-- | :- | :-- |
| `schema_version` | 是 | manifest 结构版本，整数 |
| `tool_id` | 是 | 与命名规范三元一致（见 `NAMING_AND_INTERFACES.md`） |
| `title` | 是 | 面板显示名 |
| `version` | 是 | 语义化版本 `MAJOR.MINOR.PATCH` |
| `entry` | 是 | 可执行文件相对路径（相对构建产物根） |
| `args` | 否 | 宿主启动时附加的固定参数 |
| `transport` | 是 | 当前固定为 `named-pipe`（见 §5.2） |
| `protocol_version` | 是 | 协议版本，整数 |
| `singleton` | 是 | 是否只允许一个实例 |
| `requires` | 否 | 运行前提（如 `storage`、`atrium-note`、指定字体） |
| `capabilities` | 否 | 能力声明，供宿主做入口展示与调度 |
| `perf_budget` | 否 | 与 `BUILD_AND_TEST.md` 对齐的启动/内存预算，供宿主做超时判定 |

**待确认**：字段命名与 `AtriumContracts/`（工作区规划）的落地形式，需与 `AtriumSteward` 同步后冻结。`AtriumContracts/` 目录当前尚未创建，本期以本文档与协议为权威来源。

## 3. 通信通道原则

- 通道只允许**本机**使用，禁止对公网监听。
- 通道必须支持**双向**：宿主下发命令、工具上报状态。
- 禁止：共享内存直接改宿主状态、工具写宿主配置文件、工具注册全局钩子后不注销。

## 4. 消息格式

所有消息统一信封，禁止裸文本协议：

| 字段 | 说明 |
| :-- | :-- |
| `protocol_version` | 与 manifest 一致 |
| `type` | 消息类型（见 §6、§7） |
| `id` | 请求 ID，响应必须回填同值 |
| `ts` | 时间戳（UTC，毫秒） |
| `payload` | 类型相关负载 |

编码统一 UTF-8。

### 4.1 帧格式（二进制，禁止裸文本协议）

在通道之上使用**长度前缀 + JSON 载荷**：

```text
+----------------+---------------------------+
| uint32 LE len  |  len 字节 UTF-8 JSON 载荷  |
+----------------+---------------------------+
```

规则：

1. `len` 为该帧载荷的字节数，不含自身 4 字节，小端无符号 32 位。
2. 载荷必须是 UTF-8 编码的 JSON 对象，且必须包含本节列出的信封字段。
3. 单帧载荷上限 **1 MiB**；超过上限的行为是**拒绝并断开连接**，不得截断后继续。
4. 禁止使用换行分隔 JSON（NDJSON）作为帧格式；禁止依赖"读到 EOF 才算一帧"。
5. 不允许"只发长度不发载荷"或半帧发送；发送端必须一次写完整帧。

**信封字段**：

| 字段 | 类型 | 说明 |
| :-- | :-- | :-- |
| `protocol_version` | int | 与 manifest 及协议文档一致 |
| `type` | string | 消息类型，取值见 §6 / §7 |
| `id` | string | 请求 ID；响应必须回填同值 |
| `ts` | int | UTC 毫秒时间戳 |
| `payload` | object | 类型相关负载，可为空对象 |

- 字段名与枚举值统一 `snake_case` 小写。
- 时间戳统一 UTC 毫秒整数，禁止本地时间与字符串时间。
- 出现未知 `type` 时，接收方必须忽略并记录，不得崩溃、不得断开连接（向前兼容）。

### 4.2 传输通道：Windows 命名管道（已确认）

**决策**：本机 **Windows 原生命名管道（Named Pipe）**，不使用回环 TCP，不使用公网监听。

| 项 | 约定 |
| :-- | :-- |
| 路径 | `\\.\pipe\atrium.steward.<tool_id>`，`<tool_id>` 内不得出现路径分隔符 |
| 命名空间 | 只允许用户级命名空间；**禁止** `\\.\pipe\global\` 前缀 |
| 角色 | **工具是服务端**（创建并监听管道实例），**宿主是客户端**（连接） |
| 连接数 | 同一时刻只接受**一个**有效连接；多余连接直接拒绝，不进入命令循环 |
| 权限 | 默认仅允许当前用户访问；如需放宽必须在架构文档中说明理由 |
| 消息模式 | **字节模式（byte mode）**；禁止消息模式（message mode），避免 MTU 相关的分片语义差异 |
| 实例数 | 首个实例成功创建即代表本工具已就绪；工具在收到 `shutdown` 前不得主动关闭监听 |
| 清理 | 进程退出后管道自动消失；但必须处理"上一次异常退出残留监听"的场景（重试 + 超时后返回退出码 4） |

**单实例由传输层天然保证**：当 `singleton = true` 时，工具以"创建管道名为 `<tool_id>` 的首个实例"作为抢占；创建失败即说明已有实例在运行，此时工具必须向该实例发起一次唤醒通知后以**退出码 4** 退出，不得静默抢占，也不得依赖 `.lock` 文件或进程名枚举。

**就绪顺序**：工具必须**先创建管道监听，再上报 `ready`**；反之宿主会连接失败。

**跨平台说明**：命名管道为 Windows 专有实现。macOS 侧需等价实现（`AF_UNIX` 域套接字或 `FIFO`），该差异必须在工具的架构文档中显式声明；本仓库当前主力平台为 Windows x64。

## 5. 宿主 → 工具（命令）

| 命令 | 语义 | 要求 |
| :-- | :-- | :-- |
| `context.update` | 同步工作区上下文（当前项目、笔记库、任务） | 幂等，可随时到达 |
| `activate` | 唤起窗口 / 置前 | 幂等 |
| `deactivate` | 隐藏 / 让出焦点 | 幂等 |
| `ping` | 健康检查 | 必须应答 |
| `shutdown` | 优雅退出 | 见 §6 |

## 6. 工具 → 宿主（上报）

| 类型 | 语义 | 要求 |
| :-- | :-- | :-- |
| `ready` | 初始化完成，可以接命令 | 启动后必须上报一次，且只上报一次 |
| `heartbeat` | 存活心跳 | 周期固定，写入 manifest |
| `status` | 业务状态（空闲/忙碌/错误） | 状态变化时上报 |
| `error` | 错误报告 | 附错误码与可读描述 |
| `log` | 结构化日志 | 禁止用 stdout 充当协议通道 |
| `exit` | 主动退出通知 | 附退出码与原因 |

## 7. 生命周期时序（强制）

```text
Steward                          Tool
   │  spawn(entry, args, env)      │
   │──────────────────────────────▶│
   │                               │ 初始化（不阻塞 UI 线程）
   │            ready ◀────────────│
   │◀──────────heartbeat──────────▶│ 周期心跳
   │  context.update ─────────────▶│
   │  activate ───────────────────▶│
   │                               │
   │  shutdown ───────────────────▶│
   │                               │ 落盘、释放资源、注销钩子
   │            exit(0) ◀──────────│
   │                               ✂ 进程结束
```

必须满足：

1. **启动预算**：从 `spawn` 到 `ready` 的耗时不得超过 manifest 声明的预算；超时视为启动失败。
2. **优雅退出**：收到 `shutdown` 后必须在预算内自行退出并返回 `0`。
3. **强制回收**：宿主超时后会 `terminate` 再 `kill`，工具不得依赖"宿主一定会等我"。
4. **无孤儿**：工具不得启动未被 manifest 声明的子进程；如必须启动，需声明并在退出时一并回收。
5. **单实例**：当 `singleton = true` 时，重复启动必须快速退出（非零退出码 + 明确提示），不得静默抢占。
6. **崩溃可诊断**：异常退出前尽量写入崩溃日志与退出码，便于宿主归类故障。

## 8. 退出码约定

| 退出码 | 含义 |
| :-- | :-- |
| `0` | 正常退出（含响应 `shutdown`） |
| `1` | 运行期失败 |
| `2` | 启动前置条件不满足（缺依赖、路径不可用） |
| `3` | 协议版本或 manifest 不兼容 |
| `4` | 单实例冲突 |

## 9. 上下文与配置

- 宿主通过启动参数 / 环境变量 / `context.update` 传入上下文，工具**不得**自行猜测工作区路径。
- 配置优先级：`manifest 默认值 < 工作区配置 < 用户配置 < 命令行参数`。
- 配置文件与日志编码统一 UTF-8。
- 状态类数据只允许写入 `Storage/cache/<tool_id>/`，不得写入自身仓库目录（保证工作树干净）。

## 10. 契约版本管理

- 协议变更必须升 `protocol_version`，并在 `CHANGELOG.md` 记录破坏性变更。
- 宿主与工具至少支持"当前版本 + 上一版本"兼容读取。
- 契约变更必须同步 `AtriumSteward` 侧适配层，不允许单边先行。
